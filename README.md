# dsh-better-chat

DSH 聊天增强插件。

## 功能一：审批时回车批准、Esc 拒绝（v0.1.0）

DSH 官方审批卡（`@deepseek-ai/dsh-client-ui-approval`）本身就支持
Enter 批准、Esc 拒绝，但前提是**焦点先落在审批卡里**。审批弹出时焦点
通常还在对话区，回车按下去没有反应，得先拿鼠标点一下卡片。

本插件补上这一段，不改官方逻辑：

1. **自动送入焦点**：审批卡出现时，如果你没有正在别处输入，就把焦点
   送进卡片的详情区，官方的回车/Esc 立即生效。
2. **全局兜底路由**：焦点不在卡片内时（比如点了别处又想作答），在
   document 捕获阶段接住回车/Esc，点击卡片上的按钮。回车永远点
   「允许（单次）」，不会误触「始终允许」；Esc 点「拒绝」。

防误触（与官方卡片内部规则对齐）：

- 正在任何输入框/编辑区打字时不拦截；
- 焦点已在卡片内时完全交给官方处理，不重复作答；
- 带 Ctrl/Meta/Alt/Shift、长按连发、输入法组词中不拦截；
- 回车落在某个按钮/链接上时，保留那个按钮自己的行为；
- 卡片已作答或按钮禁用时不动作。

已知边界：焦点停在另一个面板的输入框里时（例如设置页搜索框），为防
误触不会抢焦点、也不会路由按键，需要先点一下审批卡——与原生行为一致。

## 安装（DSH 桌面端）

```
dsh plugin --profile desktop add dsh-better-chat
```

完全重启 DSH 后生效。本地验证：`npm test`（判定逻辑单元测试）。

## 真机验收点

- 触发一次工具审批：不点鼠标，直接按回车应批准（单次）、Esc 应拒绝；
- 审批等待时在输入框打字，回车应照常发送/换行，不被劫持；
- 审批等待时点开别处按钮，回车应执行那个按钮而不是批准。

## 功能二：权限策略（v0.2.0）

- **去掉「完全权限」选项**：权限选择器（`/permission` 弹出菜单、composer
  权限菜单）和通用设置的默认权限下拉里，标签为「完全权限 / Full access」
  的选项会被摘除。只动界面：手动输入 `/permission danger-full-access`
  命令仍可达，那是宿主行为。
- **新会话默认「自动审查」**：第一次见到某个会话时，若它还不是自动审查，
  就通过宿主的命令通道切过去（`/permission auto`，带参命令直接生效、
  不弹风险确认）。每个会话只切一次，之后手动改走不再干预。

前置条件：**自动审查需要实验层** `@deepseek-ai/dsh-experimental-auto-review`
处于开启状态（DSH 侧栏插件页里打开，或 `dsh plugin --profile desktop add`
装上）。没开时目录里根本没有这个预设，切换会失败一次并在控制台留一条
日志，不会反复重试。自动审查的语义：每次工具调用先由当前模型审查，
放行的以完全权限执行，被拒的回落到人工审批。

真机验收点（功能二）：

1. 开实验层后新建会话 → 权限自动变为「自动审查」（composer 控件显示）。
2. 打开权限选择器 → 没有「完全权限」一项；设置里的默认权限下拉同样没有。
3. 手动把某个会话切到「工作区内修改」→ 刷新/等待后不会被改回去。
